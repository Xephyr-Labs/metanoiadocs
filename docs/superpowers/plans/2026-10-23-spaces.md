# Spaces Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every page, folder and project belongs to one space. People join spaces, and the sidebar lists joined spaces Notion-style. Home, Tasks and search favour joined spaces. Nothing about who can open what changes.

**Architecture:**
- A `spaces` table and a `space_members` table, plus a `space_id` column on `docs`, `folders` and `projects`. A data migration puts everything into a default space, "General".
- Pure helpers in `server/src/spaces.js` decide which space a new item gets and what a move takes along. A single DB function, `moveToSpace`, does every move: the new endpoints and every existing reparent path that crosses spaces.
- The client groups the lists it already loads by `space_id`.

**Tech Stack:** Express + pg (`node --test`, pure tests only), React + Vite (`vitest`, pure tests only), Playwright browser checks against a throwaway docker stack.

**Spec:** `docs/superpowers/specs/2026-10-23-spaces-design.md`

## Global Constraints

- **No change to access:**
  - `grantOn`, `doc_access`, `visibility`, the sync server's auth, share and guest routes, Inbox and notifications stay byte-for-byte unchanged.
  - No list may lose a row it returned before, except the three the spec narrows: Home, `/api/tasks` and the palette ordering.
- **Schema:**
  - All of it is additive, in `initSchema` (`server/src/db.js`), using `CREATE TABLE IF NOT EXISTS` / `ADD COLUMN IF NOT EXISTS`, in an order `db-order.test.js` accepts.
  - The backfill runs as a `data_migrations` entry named `'2026-10-spaces-general'` (`server/src/data-migrations.js`).
- **Default space:**
  - Name `General`, icon `🏠`, `is_default = true`.
  - At most one row has `is_default` (unique partial index `spaces_one_default`). It can never be deleted.
- **Every move runs in one transaction,** through `moveToSpace(client, root, spaceId)`.
- **Moves keep pins.** A pin follows its item, since a pin's space is read from the item. *Ruling: the spec said pins are dropped on a move. The code can't pin projects and pins carry no space of their own, so deriving the space is simpler, and nothing is lost.*
- **Webhook payloads stay as they are.** *Ruling: the spec's "payloads gain space_id" is deferred; no consumer needs it yet.*
- **Never push to `main`.** Work on `feat/spaces`.
- **rtk mangles some commands:**
  - Call binaries directly: `./node_modules/.bin/vitest`, `./node_modules/.bin/tsc`.
  - Run anything that pipes `2>&1` through a script file.
  - Use `rtk proxy git log` when a sha matters.
- **Copy rules:**
  - Sidebar entry: "Spaces".
  - Buttons: "New space", "Join", "Joined", "Leave space".
  - Palette heading: "Other spaces".
  - 409 message: "Move the database instead".

## Review Focus

1. **A task assigned to me in a space I never joined** must still show in Tasks, Home's My tasks and Inbox. Test in Task 6 (Tasks route) and Task 11 (browser).
2. **A cross-space drag of a page** that has sub-pages, private sub-pages from someone else, or a folder in another space must move the whole tree, lose nothing, and reload identically. Covered by Task 2's `collectMove` tests and Task 11.
3. **A brand-new user from each signup path** (setup, register, magic link) lands in General. If not, their sidebar has no spaces. Test in Task 11.
4. **Deleting a space that still holds trashed items** must be refused. Otherwise restoring from trash would hit a dangling `space_id`. Test in Task 4 (route) and Task 11.
5. **Old clients** (a stale PWA bundle, Andy's MCP) that send no `spaceId` must still create items, and those items land in the default space. Test in Task 5.

### Task 2: Pure space rules

**Files:**
- Create: `server/src/spaces.js`
- Create: `server/src/spaces.test.js`

**Interfaces:**
- Produces:
  - `resolveSpace({ parentSpace, folderSpace, requested, fallback }) => string`
    - Rules, in order: `parentSpace` (a sub-page, sub-folder or sub-project), then `folderSpace` (a top-level page in a folder), then `requested`, then `fallback`.
    - Empty or undefined values are skipped.
  - `collectMove(graph, root) => { docIds: string[], folderIds: string[], projectIds: string[], clearFolderDocIds: string[] }`
    - `graph = { docs: {id, parent_id, folder_id, kind}[], folders: {id, parent_id}[], projects: {id, parent_id, doc_id}[], tasks: {project_id, doc_id}[] }`
    - `root = { type: 'doc' | 'folder' | 'project', id }`
    - **doc root:** the doc and all its descendants by `parent_id`.
    - **folder root:** the folder and its sub-folders, every top-level doc (`parent_id` null) whose `folder_id` is in that set, and each such doc's descendants.
    - **project root:** the project and its sub-projects. Also each project's `doc_id` page, and each task page that is `kind === 'task'` and is the `doc_id` of a task in those projects, both with their descendants.
    - `clearFolderDocIds`: moved docs whose `folder_id` names a folder that is *not* moving. Their `folder_id` must be cleared.
  - `isProjectOwnedPage(graph, docId) => boolean`: true when the doc is a `kind === 'task'` page, or is some project's `doc_id`.
  - `byJoinedFirst(rows, joined: Set<string>) => rows` (stable): rows whose `space_id` is in `joined` come first, in their existing order.

**Files:**

**Interfaces:**
- Consumes: `collectMove` and `isProjectOwnedPage` (Task 2).
- Produces:
  - `loadSpaceGraph(client) => Promise<graph>`. Selects the non-deleted `docs(id,parent_id,folder_id,kind)` (trashed included, so trash restores stay consistent), `folders(id,parent_id)`, `projects(id,parent_id,doc_id)` and `tasks(project_id,doc_id) WHERE doc_id IS NOT NULL`. *ponytail: loads the whole graph per move; a recursive CTE if workspaces get large.*
  - `moveToSpace(client, root, spaceId) => Promise<{ docs: number, folders: number, projects: number }>`. Inside the caller's transaction:
    1. `collectMove`
    2. `UPDATE … SET space_id`

  - Routes, each body `{ spaceId }`, each running `BEGIN`/`moveToSpace`/`COMMIT`:
    - `POST /api/docs/:id/space`: needs `editGrant` on the doc. 409 `{ error: 'Move the database instead' }` when `isProjectOwnedPage`.
    - `POST /api/folders/:id/space` and `POST /api/projects/:id/space`: `requireUser`.
    - 404 for an unknown space or item.
  - `GET /api/move-preview?type=doc|folder|project&id=&spaceId=` returns `{ docs, folders, projects, hidden: boolean }`. Counts include only docs the caller can see (the inline visibility predicate). `hidden` is true when the move takes more docs than the caller can see.
